# collect

## WSL / Linux ARM64 共用源码

两端使用同一仓库和启动命令，分别在各自机器编译；不要复制或共享 `build_mvs` 构建目录。
需要 C++17、CMake、OpenCV（core/imgproc/imgcodecs/calib3d/photo）、Qt5 Quick / QuickControls2 及对应 QML 模块、
海康 MVS 和 CGXi 机器人 SDK。SDK 的动态库必须与目标 CPU 架构一致。
工程仅提供 GUI，已移除命令行采样、离线工具和 OAK 后端。相机后端仅支持 MVS；无需再选择后端。旧配置中的 `cam_port` 会被忽略。

```bash
./build_collect.sh -DCGX_SDK_DIR="/path/to/robot-sdk" -DMVS_SDK_DIR=/opt/MVS
./run_collect.sh
```

机器人 SDK 根目录包含 `include/robotapi.h`。自动识别新版 SDK 的
`libs/linux/x64`、`libs/arm/aarch64` 和旧版的 `libs/x64`、`libs` 布局。
特殊布局可额外传入 `-DCGX_SDK_LIB_DIR="/path/to/libraries"`。
路径保存在本机 CMake 缓存，后续直接运行 `./build_collect.sh`。
GUI 与测试使用父项目解析的 SDK 路径，SDK 文件无需提交到 Git。

`run_collect.sh` 在 WSLg 下自动补充缺失的 `DISPLAY` 并默认使用 Qt 软件渲染；
ARM64 沿用本机图形环境。采集配置位于 `build_mvs/config.yaml`。
界面启动不要求连接设备；真实采图和机器人操作需要相应网络或 USB 设备可达。

## collect 图像采集分支

本分支提供图像采集、法兰与 TCP 位姿保存、九点采图和手动 TCP 移动，不执行标定。已有标定结果可用于去畸变。

安装海康 MVS、OpenCV、Qt5 和机器人 SDK 后，在仓库根目录运行：

```bash
./build_collect.sh
./build_mvs/collect-mvs
```

机器人 SDK 放在 `libs/cr_sdk`；本机工作目录已通过忽略的 `libs` 符号链接复用
`/home/nvidia/work/caitu-nano-new/libs`。首次配置将 `config/collect.example.yaml`
复制为 `build_mvs/config.yaml`，后续构建保留已有配置。可以在“设置 → 设备”填写
相机 IP 和分辨率，保存后返回主页点击“连接相机”。预览与拍照不需要机器人连接。
默认相机 IP 为 `192.168.66.253`、分辨率为 `4024×3036`，机器人为
`192.168.66.14:2323`；内部固定使用端口 `2323` 和密码 `123`，界面不提供端口与密码编辑。采图连接按 IP 选择相机，忽略旧设置中的序列号。

每个缺失字段单独使用默认值。配置文件缺失或损坏时程序仍可启动，使用内置默认值并记录日志。
可从 `config/collect.example.yaml` 复制初始配置，常用字段如下：

轴角单位 °。未连接机器人、读取失败或出现非有限数值时，六个字段为 `null`，界面日志
提示原因，图片正常保存，不复用上一张位姿。图片保存后等待本次 SDK 读取结束再完成操作；
通信超时可能延长本次操作结束的等待，但不会阻止图片写入。
当天目录首次成功读取位姿时，另存 `T_base_flange.json`，仅含 `T_base_flange` 4×4矩阵，
平移单位 m；已有文件不覆盖。首次读取失败时，后续有效读取会补存该初始矩阵。
任何曝光取帧失败或恢复曝光设置失败，本次均不保存。文件名包含时间戳和随机编号，
原子写入，固定保存到 `~/Pictures/caitu-collect/<yyyy-MM-dd>/`，每次拍照自动创建
或复用当天文件夹；日期和文件时间均以按下拍照时的本机时间为准，跨午夜的曝光序列
仍归到按下拍照时的日期。旧的自定义保存目录设置不再生效。拍照曝光列表通过
`config.yaml` 记住。融合序列使用五个输入框，空白档位不参与融合，至少填写两个不同值。
默认仍使用四档曝光，第五框留空。

### 实时 TCP 位姿与手动移动

主页面持续读取当前所选 TCP 的基坐标系位姿，显示 X/Y/Z（mm）和 Rx/Ry/Rz（轴角 °），保留两位小数。
主页、手动移动页的当前位姿与目标解析结果统一按 `X,Y,Z,Rx,Ry,Rz` 显示，
点击“复制”即可复制六个英文逗号分隔的数值，直接粘贴到目标输入框；无效或过期的当前位姿不可复制。
空闲时约每 200 ms 请求一次；运动时在同一个机器人工作线程中串行刷新，避免与运动指令并发使用 SDK。
切换工具、断开、读取失败或数据超过 1 秒未更新时立即显示 `—`；旧工具、旧连接的迟到结果会被丢弃。
曝光采集或 SDK 调用耗时较长时可能暂时显示数据过期，不将旧读数当作当前坐标。

选择 TCP 后进入“手动移动 TCP”，在单一输入框中填写 `X,Y,Z,Rx,Ry,Rz`，支持中英文逗号。
这是所选 TCP 在基坐标系中的绝对位姿，位置单位 mm，姿态为轴角 °，不是六个关节角。
解析结果在页面中只读预览；仅点击“移动到目标”执行，输入框 Enter、拍照快捷键均不会触发运动。

执行前重新读取工具偏移，检查机器人静止、逆解和关节安全限位；运动使用明确的所选工具偏移，
不修改机器人当前激活工具。直线速度 10 mm/s、加速度 20 mm/s²，移动期间锁定编辑与返回。
位置误差不超过 0.05 mm、姿态误差不超过 0.2°，且停止后连续稳定 1.2 秒才算完成，最长等待 180 秒。
SDK 未提供当前安全模式查询，因此预检查同时采用 Normal 与 Reduced 的关节位置限位；
此检查不代表路径无碰撞，操作前应确认目标、工具及整段直线路径。
停止或异常后独立确认机器人已停止，未确认则保留故障锁和“重试停止”，禁止断开及新操作。
手动移动本身不拍照，图片及位姿保存策略不变。

### 九点采图

手动将机器人移到基准位置并停止，在左侧选择“九点”并设置 X、Y 偏移，
点击“开始九点采集”。每次开始都读取当前位置作为本次基准，默认各偏移 10 mm，
支持 0.1～50 mm。机器人和相机预览必须已连接就绪，不要求选择 TCP。
九宫格对角点距基准不得超过 50 mm，即 `sqrt(ΔX²+ΔY²) ≤ 50 mm`；
例如 X/Y 各 10 mm 可以，均为 40 mm 时拒绝执行。
开始前检查全部九个目标的逆解；目标相对基准的任一关节变化超过 30° 时拒绝执行。

以当前法兰基准位为九宫格中心，按从左到右、从上到下的 1～9 顺序拍照。
列方向为 Base X−、0、X+；行方向为 Base Y+、0、Y−；第 5 点为基准位。
各点欧拉 Rz 相对基准的变化为：

| BASE Y / BASE X | −ΔX | 0 | +ΔX |
|---|---|---|---|
| +ΔY | ① 0° | ② +15° | ③ −15° |
| 0 | ④ −20° | ⑤ 0°（基准） | ⑥ +20° |
| −ΔY | ⑦ +15° | ⑧ −15° | ⑨ 0° |

姿态使用 ZYX 欧拉约定 `R = Rz · Ry · Rx`，保持欧拉 Rx/Ry 和 Z 高度，
仅改变欧拉 Rz，角度均相对同一基准、不累加。
实现以等价的 `Rz(增量) · R基准` 计算旋转，再转回 SDK 的轴角格式，避免欧拉角奇异点。
因此保存的轴角 rx/ry/rz 数值可能同时变化，不能直接把增量加到轴角 rz 上。
旋转不改变该点的 XYZ，XY 仅由九宫格平移产生。
每个偏移点拍完后沿直线回到原始基准位和姿态，再去下一点，中途返回不拍照。
明确使用基坐标系和零工具偏移，不改变机器人当前 TCP。
直线速度使用设置中的移动速度（1～1000 mm/s），加速度 20 mm/s²，逐段停止，无轨迹交融。
到位须满足位置误差不超过 0.05 mm、姿态误差不超过 0.2°，
且机器人已停止并持续稳定 1.2 秒；单段到位等待至少 30 秒，低速时根据 50 mm 路程延长。
逆解检查不代表碰撞检测，使用前需确认基准到各点之间的平移及旋转路径可通行。

每个点完整采集当前曝光序列并融合，图片及位姿等记录全部提交成功后才移动。
**保存方式与手动拍照相同**：仍为当天目录中的 `capture_<时间戳>_<随机号>_fused.png`
及同名六字段法兰位姿 JSON，去畸变启用时保留现有原图、校正图和像素坐标记录。
每张以实际开始拍照时的时间归档，不增加分组目录、分组文件或点位后缀；
也不替换当天已有的 `T_base_flange.json`。本次基准、拍摄位置和图片路径记入现有诊断日志。

执行中显示点位及阶段进度，锁定曝光、偏移、设备连接、TCP 切换、手动移动和其他采图操作。
正常完成九次采图并回到基准后显示完成。点击现有“停止”，或遇到运动、通信、
图片/位姿记录失败时，终止后续动作；运动期间请求机器人停止，停止指令失败会明确提示。
已保存的数据保留，不在失败后自动返程。任务结束或停止指令返回成功不代表已经停稳；
结束前连续三次检查机器人运动状态和停止模式。无法确认停止时保留故障锁，禁止断开、
新操作和关闭窗口，现有按钮改为“重试停止”。重试后独立确认停止才解锁；
即使应用被直接析构，停止未确认时也不销毁机器人 SDK 句柄。
单次手动拍照仍允许机器人未连接或位姿读取失败，
此时保留图片并记录空位姿；九点采图则不会以空位姿继续下一点。

### 一键去畸变

采图程序启动时，自动读取**可执行程序所在目录**的 `param/hand_eye_result.yaml`，
79 上对应 `/home/nvidia/Desktop/COLLECT/param/hand_eye_result.yaml`。
请放入当前相机、镜头和采集分辨率下的真实标定结果，更新文件后重启程序。
不会自动套用仓库根目录的示例文件。去畸变使用 `camera_matrix`（3×3 内参）和
`distortion_coefficients`（也兼容旧键名 `dist_coeffs`），仅有 `T_flange_camera` 手眼矩阵不足以去畸变。
支持标准 OpenCV 模型的 4、5、8、12、14 项畸变系数，不支持鱼眼模型。
文件包含 `image_width`、`image_height` 或 `camera_serial` 时，会校验实际相机尺寸及身份，
不匹配则拒绝启用；旧文件缺少尺寸时可加载，但日志提示分辨率未经验证，需确认与标定时一致。
不按比例猜测或缩放内参。缺失、损坏或无效参数会显示不可用原因，不影响原有采图。

去畸变开关位于“设置 → 成像”的预览与校正卡片。连接相机且标定参数有效后可启用，
按钮显示“去畸变已启用”；再次点击关闭。启动和断开相机后默认关闭，
仅暂停预览会保留开关。预览画面标注去畸变状态，设置页显示参数校验结果及不可用原因。
启用后，实时预览与后续每次拍照都使用同一组映射；拍照先完成多曝光融合，再去畸变。
输出尺寸等于融合图尺寸，不按 `validPixROI` 裁剪，也不额外缩放或平移。边缘可能出现黑边。
计算与当前生产算法一致：原始内参先按 float 精度往返，再以 `alpha=1`、
`centerPrincipalPoint=false` 得到新内参，并用完整精度的新内参建立 `CV_16SC2` 映射。
彩色图使用线性插值，边界填黑。采集程序不额外翻转图像。
去畸变不依赖机器人，也不执行机器人运动或静止检查。

启用时，同一天目录内保存两张 PNG：`capture_…_fused.png` 为原始融合图，
`capture_…_fused_undistorted.png` 为去畸变图。最近图片路径指向校正图；一次拍照计数增加一张。
两张图各有同名 JSON，使用同一次读取的六维法兰位姿；读取失败仍保存图片并记录六个 `null`。
去畸变图另有 `capture_…_fused_undistorted.pixel_frame.json`，记录
`pixel_frame=production_alpha1_undistorted_full_frame`、原始内参、float 往返后的计算内参、

## 无硬件测试

GUI 需要相机与机器人 SDK；测试本身不连接设备。仅运行软件回归时可不安装 SDK：

```bash
cmake -S . -B build_tests -DBUILD_QT_GUI=OFF -DBUILD_TESTS=ON
cmake --build build_tests -j4
ctest --test-dir build_tests --output-on-failure
```

`build_collect.sh` 构建 GUI 和全部可用测试，再运行完整 CTest。
黑白 MVS 帧仍通过原有 SDK 像素转换进入 BGR8 融合链路；本轮未修改该转换。
`collection_synthetic_bgr_fusion_png` 仅用 OpenCV 将合成灰度图转为三通道相等的 BGR，
验证融合和 PNG 回读，不覆盖 MVS Mono8 → BGR 转换、SDK 取帧或真实曝光。
源码回归不代表真实相机、曝光时序或机器人采集已验证，仍需分别进行黑白/彩色设备验收。

采集配置仅按 IP 选相机；旧 `cam_sn`、`robot_port`、`robot_pwd` 键不参与连接，示例不再列出。
实际设备序列号仍用于诊断及已有去畸变参数的身份校验。
快门闪光使用独立历史计数：初始化或切换控制器时建立当前计数基线，计数增加才闪光；
计数减少时清除动画并重建基线，失败、取消及计数不变的共享通知不会再次闪光。
UI 回归模拟真实 `collectionChanged` 共享 NOTIFY，包括开始采集时计数尚未变化的通知。
这是消除绑定与通知顺序依赖的改进，不作为已复现“首张必不闪”的证明。
