# calibri_nano

## collect 图像采集分支

本分支基于 `origin/codex/mvs-support`（`98173d3`）。默认 GUI 是图像采集界面；
使用 `collect-mvs --calibration` 可进入原标定界面。

安装海康 MVS、OpenCV、Qt5 和机器人 SDK 后，在仓库根目录运行：

```bash
./build_collect.sh
./build_mvs/collect-mvs
```

机器人 SDK 放在 `libs/cr_sdk`；本机工作目录已通过忽略的 `libs` 符号链接复用
`/home/nvidia/work/caitu-nano-new/libs`。首次配置将 `config/collect.example.yaml`
复制为 `build_mvs/config.yaml`，后续构建保留已有配置。可以修改配置或在界面中填写
相机 IP 和分辨率，然后点击“连接并预览”。预览与拍照不需要机器人连接。
默认相机 IP 为 `192.168.66.253`、分辨率为 `4024×3036`，机器人为
`192.168.66.14:2323`；内部固定使用端口 `2323` 和密码 `123`，界面不显示端口与密码。采图连接按 IP 选择相机，忽略旧设置中的序列号。

“拍照保存”按钮、空格、`S` 和 `Ctrl+S` 每次都重新采集曝光列表中的全部图像，
再用 OpenCV Mertens 融合为一张无损 PNG；实现参考
`det-xialiao-MVS-nano/det-src/cameras/AICamera.hpp` 的 `method_mertens`。
曝光值使用 μs，支持 2～5 个不同值。默认列表为 `5000,8500,14500,25000`，
拍照前根据实际设备范围检查。输入框获得焦点时，空格、`S` 和 `Ctrl+S` 均不会触发拍照。多曝光期间暂停预览取帧，完成后恢复；相机与被拍物体应静止。
拍照直接采集多曝光图像，不查询机器人的静止状态；机器人连接状态不影响拍照。
拍照时并行调用 `cr_get_AssignTCP_Pose`，传入六个零工具偏移，读取法兰在基坐标系下的
轴角位姿。每张 PNG 旁保存同名 JSON，仅含 `x,y,z,rx,ry,rz` 六个字段，位置单位 mm，
轴角单位 °。未连接机器人、读取失败或出现非有限数值时，六个字段为 `null`，界面日志
提示原因，图片正常保存，不复用上一张位姿。图片保存后等待本次 SDK 读取结束再完成操作；
通信超时可能延长本次操作结束的等待，但不会阻止图片写入。
当天目录首次成功读取位姿时，另存 `T_base_flange.json`，仅含 `T_base_flange` 4×4矩阵，
平移单位 m；已有文件不覆盖。首次读取失败时，后续有效读取会补存该初始矩阵。
任何曝光取帧失败或恢复曝光设置失败，本次均不保存。文件名包含时间戳和随机编号，
原子写入，固定保存到 `~/Pictures/caitu-collect/<yyyy-MM-dd>/`，每次拍照自动创建
或复用当天文件夹；日期和文件时间均以按下拍照时的本机时间为准，跨午夜的曝光序列
仍归到按下拍照时的日期。旧的自定义保存目录设置不再生效。拍照曝光列表通过本机
Qt 设置记住。融合序列使用五个横向输入框，空白档位不参与融合，至少填写两个不同值。
默认仍使用四档曝光，第五框留空。相机与机器人连接按钮使用同一列。
界面采用深灰 Bento 布局，顶部左卡为设备连接，右卡为五格曝光、拍照与独立点位保存，图片目录按钮位于卡片标题右侧。
左侧完整取景器；预览曝光默认为 `12000 μs`，输入及“应用”放在右侧独立的预览曝光卡片内。
右侧同时显示采集数量、归档日期、独立点位数量、最近图片和操作日志。操作日志记录带时间的
状态变化，保留最近 200 条；详细诊断继续写入原日志文件。

“一键调平”需要预览画面和机器人连接。手眼矩阵固定读取**可执行程序所在目录**的
`param/hand_eye_result.yaml`（本机为 `build_mvs/param/hand_eye_result.yaml`），
页面无需填写或显示手眼文件路径。文件包含 `T_flange_camera`（相机到法兰的 4×4 变换），
支持 OpenCV 矩阵或 16 个数值的行优先列表。平移默认以米计，毫米矩阵请在 YAML 顶层
设置 `translation_unit: mm`，米可写 `translation_unit: m`。

有有效手眼矩阵时，调平使相机光轴指向机器人基坐标系 -Z，目标姿态保留镜头中心位置
与水平朝向。文件不存在或没有 `T_flange_camera` 时，按相机与法兰方向平行处理，
保持当前法兰位置，使法兰 +Z 垂直向下，镜头平面水平；不自动套用示例矩阵。
文件存在但无法读取、矩阵格式或单位无效时报告失败。
计算当前位姿、求解逆运动学后通过已有机器人运动接口执行，实际到位倾角超过 1°
时报告失败。“停止”可取消当前操作，机器人运动沿用已有接口的停止和超时处理。
基坐标系 Z 轴应与现场竖直方向一致。

点击“保存法兰位姿”展开点位名称输入框，再点击“确认保存”或按 Enter 保存；Esc 或“取消”收起。
名称留空时使用时间戳命名。独立点位使用相同零工具偏移接口读取，既不拍照，也不检查机器人静止状态。
保存到当天目录的 `pose_<名称或时间戳>.json`，仅含 `x,y,z,rx,ry,rz`，位置为基坐标系 mm，旋转为轴角 °。
名称禁止路径和文件名特殊字符；重名自动追加编号，已有文件不覆盖。读取失败时明确记录日志，不写空位姿文件。
首次有效独立点位也可创建当天初始矩阵，已有 `T_base_flange.json` 不覆盖。右侧显示本次独立点位保存数量。

### 一键去畸变

采图程序启动时，自动读取**可执行程序所在目录**的 `param/hand_eye_result.yaml`，
79 上对应 `/home/nvidia/Desktop/COLLECT/param/hand_eye_result.yaml`。
请放入当前相机、镜头和采集分辨率下的真实标定结果，更新文件后重启程序。
不会自动套用仓库根目录的示例文件。去畸变使用 `camera_matrix`（3×3 内参）和
`distortion_coefficients`（也兼容旧键名 `dist_coeffs`），仅有 `T_flange_camera` 手眼矩阵不足以去畸变。
支持标准 OpenCV 模型的 4、5、8、12、14 项畸变系数，不支持鱼眼模型。
文件包含 `image_width`、`image_height` 或 `camera_serial` 时，会校验实际相机尺寸及身份，
不匹配则拒绝启用；旧文件缺少尺寸时可加载，但日志提示分辨率未经验证，需确认与标定时一致。
不按比例猜测或缩放内参。缺失、损坏或无效参数会显示不可用原因，不影响原有采图。

“一键去畸变”位于实时预览标题栏、“暂停预览”左侧。连接相机后可启用，
按钮变绿并显示“去畸变已启用”；再次点击关闭。启动和断开相机后默认关闭，
仅暂停预览会保留开关。右侧预览曝光卡片显示参数和开关状态。
启用后，实时预览与后续每次拍照都使用同一组映射；拍照先完成多曝光融合，再去畸变。
保持原始图像宽高和内参，不自动裁剪或缩放，边缘可能出现黑边。
去畸变不依赖机器人，也不执行机器人运动或静止检查。

启用时，同一天目录内保存两张 PNG：`capture_…_fused.png` 为原始融合图，
`capture_…_fused_undistorted.png` 为去畸变图。最近图片展示校正图；一次拍照计数增加一张。
两张图各有同名 JSON，使用同一次读取的六维法兰位姿；读取失败仍保存图片并记录六个 `null`。
初始 `T_base_flange.json` 继续仅保存一次。关闭去畸变后沿用原来的单张融合图保存方式。

自动检查覆盖配置解析、调平几何与融合、图片附属位姿与独立位姿格式一致性、重名保护、首次矩阵保留、失败不写假位姿，以及界面快捷键、点位命名交互和最小窗口布局。真实取帧、曝光恢复、位姿读取与机器人调平运动需连接设备验收。
`collection_undistortion` 检查参数校验、与 OpenCV 参考结果的一致性、校正图主路径、原图保留、
关闭时的单图保存和两张图的位姿一致性；界面检查覆盖去畸变开关及最小窗口布局。
拍照取消会等待当前曝光序列返回，再丢弃本次结果。

## 全自动眼在手外标定

- 内部求解矩阵 `X` 使用
  `inv(T_base_flange_i) * X * T_camera_board_i` 在法兰坐标系下保持不变
  的约束。生产 YAML 中历史键名 `T_base_camera` 保存 `inv(X)`，以保持与
  2026-06-27 已现场验证结果及既有消费端一致；平移单位为米。
- 默认仍生成 `3^6 = 729` 个候选，保留可达且路径连通的采集目标；
  按关节路径排序、检查相邻关节跳变，必要的过渡点不采图。
  全自动流程不使用半自动的 90 个选点上限。
- 采集到位后等待 1200 ms，丢弃两帧，每个位置最多尝试三次采图。
  每帧至少 12 个角点；求解至少 12 帧，MAD 过滤后还须保留至少 60%。
- 求解复用五算法共识与代表解精化。最终平移 RMS/P95 门限为 5/8 mm，
  旋转 RMS/P95 门限为 1/2 度；至少三个算法成功，算法间最大差异不超过
  10 mm 和 1 度。这些是程序验收门限，不代表实际定位精度保证。
- GUI 必须加载有效的 `param/eye_to_hand_config.yaml`。
  生产结果保存失败会报告失败，不会显示标定成功。
- 每次采集保存到 `eye_to_hand/run_<时间戳>_<编号>/`，GUI 显示本次目录，
  历史采集不再被清空。中断采集保留 `.collection_incomplete` 标记，拒绝自动复算；
  完整数据严格检查 CSV 行与编号图像的一一对应关系。

无硬件回归测试：构建 `test_eye_to_hand_solver` 后运行
`ctest --test-dir build_mvs --output-on-failure`。测试使用合成位姿，不连接设备。
眼在手外矩阵方向必须用 2026-06-27 现场基准做回归验证；禁止仅凭键名改动
求逆约定。

## 标定审计部署边界

- 掉电持久性保证当前仅适用于 Linux/Jetson。Windows 构建尚未实现等价的
  `FlushFileBuffers`、目录项持久化和覆盖已有目标文件的原子发布语义，不能按
  Phase 1.1 的掉电安全标准验收。
- 标定结果发布采用单写者模型。同一生产 YAML 路径同一时间只允许一个 GUI、
  CLI 或离线 Replay 进程写入；当前版本不提供跨进程文件锁。
- 已封存 Session 是不可变审计数据。Replay 输出必须位于源 Session 目录之外，
  工具会在复算前解析相对路径、`..` 和符号链接并拒绝越界输出。

## Phase 3 LOO 稳定性诊断

LOO 是显式离线深诊断，不在在线标定或普通 Replay 中默认执行，避免重复求解
影响产线节拍。对封存 Session 执行：

```text
offline_eye_in_hand --replay-session <session_dir> <output.yaml> --loo
```

也可对普通离线数据集执行：

```text
offline_eye_in_hand <calibration_dir> <camera_params.yaml> <output.yaml> --loo
```

报告中的 `hand_eye_loo_diagnostics` 同时包含：

- `fixed_final_inliers`：只从最终内点集删除一帧，锁定完整结果选中的 solver，
  不重新运行 MAD，用于隔离单帧影响；
- `full_pipeline`：删除一帧后重新运行 MAD、五算法共识、SE(3) medoid 和精化，
  同时记录最终内点集合相对完整结果的新增和移除项。

两种模式均输出平移和旋转影响的 mean、P95、max、最高影响帧及失败次数。
深诊断最多使用 4 个并行 worker，结果按原始帧顺序持久化；每 25 次试验保存一次
进度。计算量随帧数明显增长，建议使用产线标准的约 90 帧数据集执行，超大历史
数据集应预留更长的离线分析时间。
